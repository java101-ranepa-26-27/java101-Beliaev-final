# Авиакасса. Итоговый проект, вариант 11

Консольное приложение на Java 21. Данные хранятся только в памяти и теряются после выхода.
Рейсы, пассажиры, эконом- и бизнес-билеты; продажа и возврат; поиск и статистика.

## Сборка и запуск

Для сборки подходит JDK 21 или установленный JDK 23. Укажите выбранный JDK
в JAVA_HOME и добавьте его каталог bin в PATH. Отдельная установка JDK 21 не требуется.
Gradle использует JDK, на котором запущен, и компилирует с параметром --release 21:
классы и доступные API остаются совместимыми с Java 21 по заданию.
Gradle 8.10 поставляется через wrapper; JUnit 5.10.0 закреплён в build.gradle.
При первой сборке нужен интернет для загрузки Gradle и зависимостей из Maven Central.

Из корня проекта в PowerShell:

```powershell
.\gradlew.bat clean build
.\gradlew.bat test
.\gradlew.bat run --console=plain
```

На Linux/macOS:

```sh
sh ./gradlew clean build
sh ./gradlew test
sh ./gradlew run --console=plain
```

Результаты тестов: build/reports/tests/test/index.html.
Главный класс: ru.ranepa.airline.Main. Старый Hello сохранён отдельно.
В IDE можно оставить установленный JDK 23 для проекта и Gradle, консоль в UTF-8.
В настройках Gradle JVM выберите тот же JDK 23, затем обновите Gradle-проект.
В gradle.properties задана совместимая с системой кодировка служебных файлов Gradle:
это позволяет запускать тесты из путей с кириллицей на Windows. Исходники и ввод используют UTF-8; вывод задачи run согласован с кодировкой Gradle.

## Как пользоваться

Выберите номер пункта меню. Дата вылета вводится в формате дд.мм.гггг чч:мм,
например 20.12.2099 14:30. Дата обязана быть в будущем.
Для быстрого добавления рейса выберите пункт 2: вылет через сутки, вместимость 100 мест.
Перед продажей заведите рейс и пассажира. Для продажи и возврата нужны номер рейса и паспорт.
Цена вводится в рублях, например 1250,50 или 1250.50, не более двух знаков после запятой.
Пункты 9 и 12 показывают билеты и статистику. Пункт 0 завершает программу.

## Правила

- Номер рейса уникален без учёта регистра. Паспорт уникален после удаления пробелов по краям.
- На один рейс пассажиру можно продать один действующий билет. После возврата покупка снова доступна.
- Места общие для эконома и бизнеса. Продажа на вылетевший или заполненный рейс запрещена.
- Цена хранится в копейках (long); BigDecimal применяется только для точного перевода ввода в копейки.
- Выручка считается по действующим билетам: возврат уменьшает выручку и освобождает место.
- Загрузка показывается в процентах. Поиск: точное название города назначения без учёта регистра.
- В фильтре доступны только будущие рейсы со свободными местами.
- Время местное для компьютера, без перевода часовых поясов. Паспорт и телефон хранятся как непустой текст.
- Счётчик Flight общий для процесса: считает успешно созданные объекты рейсов, не уменьшается.
- Отмена рейсов, сохранение в файлы, сортировка и напоминания не реализованы: это необязательные функции.

## Устройство

Классы разделены по назначению, как в учебном каркасе:

```text
ru/ranepa/airline/
  Main.java
  domain/
    Flight.java
    Passenger.java
    Ticket.java
    EconomyTicket.java
    BusinessTicket.java
    Validation.java
  application/
    AirlineOffice.java
    FlightService.java
    PassengerService.java
    TicketService.java
    port/
      FlightRepository.java
      PassengerRepository.java
      TicketRepository.java
  infrastructure/
    ConsoleMenu.java
    InMemoryFlightRepository.java
    InMemoryPassengerRepository.java
    InMemoryTicketRepository.java
```

domain содержит сущности и их проверки. application содержит правила работы кассы:
рейсы, пассажиры, продажа, возврат и статистика. AirlineOffice объединяет сервисы
и даёт меню одну точку доступа к операциям кассы.
application/port определяет небольшие интерфейсы хранения, infrastructure реализует
их через ArrayList и содержит консольное меню. Хранилища возвращают копии списков.
Main создаёт хранилища и сервисы и передаёт зависимости через конструкторы.

Связь с SOLID:

- S: меню занимается вводом и выводом, сервисы правилами, репозитории хранением.
- O: описание нового вида билета можно добавить через наследника Ticket,
  не меняя общий вывод списка билетов. Для отдельной команды продажи потребуется расширить меню.
- L: эконом- и бизнес-билеты используются в одном List<Ticket> и соблюдают общие проверки цены.
- I: у каждого хранилища свой маленький интерфейс с нужными ему операциями.
- D: сервисы зависят от интерфейсов репозиториев; конкретные хранилища выбираются в Main.

Поиск написан обычными циклами. Тесты повторяют разделение на application и infrastructure;
TestOfficeFactory создаёт связанную кассу для тестов.
Конструкторы проверяют данные, свободные места меняются через проверяемые методы.
Номер рейса и паспорт нельзя изменить после создания, чтобы не нарушить связи билетов.
Имя и телефон пассажира можно изменить через методы с проверками.

В тестах есть переполненный рейс, возврат и повторный возврат, неверные данные, поиск,
выручка, перегрузка конструктора, полиморфизм и сценарии консольного ввода.
