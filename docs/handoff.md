Состояние на 16.11.2026: обязательные функции реализованы, работа в ветке task-final.
Коммиты не созданы, изменения не отправлены на GitHub.

## Выполнено

- Совместимость с Java 21 (--release 21), сборка на JDK 21 или 23, Gradle Wrapper 8.10,
  JUnit Jupiter 5.10.0 и явный JUnit Platform Launcher. Отдельный toolchain JDK 21 не требуется.
- Рейсы и пассажиры, проверка полей, уникальные номера рейсов и паспорта.
- Полный и сокращённый конструкторы рейса, статический счётчик.
- Эконом- и бизнес-билеты, наследование и разное описание билетов.
- Продажа и возврат, контроль мест, поиск по городу назначения, фильтр, статистика.
- Меню с обработкой неправильных чисел, дат, пустых полей и конца ввода.
- 19 JUnit-тестов, отдельная проверка консольного сценария продажи и возврата.
- Сборка и запуск проверены из отдельного каталога с пробелом и кириллицей;
  gradle.properties устраняет несовпадение кодировок аргументов Gradle на Windows.
- Исходное задание сохранено в docs/assignment.md, старый README в docs/practice-1.md.
- Старый Hello и существующие настройки IDE сохранены.

Структура разделена по назначению: domain (сущности), application (три сервиса
и фасад AirlineOffice), application/port (интерфейсы репозиториев), infrastructure
(хранилища в памяти и ConsoleMenu). В Main выбираются конкретные хранилища
и передаются через конструкторы. Тесты разделены на application и infrastructure.
AirlineOffice сохраняет единую точку доступа для меню; подробное объяснение SOLID есть в README.
Код находится в src/main/java/ru/ranepa/airline, тесты в src/test/java/ru/ranepa/airline.

## Как перенести

Для сборки нужен JDK 21 или 23. На новом компьютере задайте JAVA_HOME на выбранный
JDK и добавьте bin в PATH. В IDE выбирайте тот же JDK для Gradle JVM.
Готовые классы совместимы с Java 21 благодаря --release 21.
Переносите src, docs, README.md, build.gradle, settings.gradle, gradle.properties, gradlew, gradlew.bat,
gradle/wrapper и .gitignore. Важно сохранить gradle-wrapper.jar.
Для первого запуска Gradle нужны сеть и доступ к Maven Central.
Сборку build и кэш .gradle, настройки IDE, токены и локальные пути переносить не нужно.
Историю Git удобнее получать клонированием после отдельно разрешённых коммитов и push.
Пока коммитов нет, перед переносом сохраните копию текущих исходников: клон их не содержит.

PowerShell, из корня проекта:

```powershell
.\gradlew.bat clean build
.\gradlew.bat test
.\gradlew.bat run --console=plain
```

Linux/macOS: sh ./gradlew clean build; sh ./gradlew test; sh ./gradlew run --console=plain.
Отчёт тестов: build/reports/tests/test/index.html. Кодировка UTF-8.

## Принятые правила

Цена вводится в рублях с точностью до копеек, хранится как long в копейках.
Один действующий билет на пассажира и рейс; после возврата можно купить снова.
Возврат освобождает место и уменьшает выручку. Вместимость общая для двух классов.
Быстрое создание: 100 мест и вылет через сутки. Время местное для компьютера.
Поиск по точному названию города назначения без учёта регистра.
Данные только в памяти; при перезапуске создаётся пустая касса.
Отмена рейсов и четыре необязательные возможности задания не реализованы.

## Следующие шаги

1. Открыть Main в IDE с установленным JDK 23 (либо JDK 21) и самостоятельно пройти меню.
2. Разобрать устройство классов и тесты перед защитой; проверить допустимость средств
   по фактически пройденным темам (ввод цены использует BigDecimal, тесты используют лямбды).
3. Подготовить объяснение разделения ответственности и зависимости сервисов от интерфейсов.
4. После отдельного разрешения пользователя разбить изменения на согласованные коммиты.
5. Push и PR task-final → main выполнять только после явного запроса пользователя;
   в описании PR своими словами перечислить проверенные граничные случаи.
